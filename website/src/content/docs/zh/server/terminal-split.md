# 多窗格分屏

多窗格分屏适合需要同时观察和操作多个环境的场景：一边看生产日志，一边在测试机验证命令，旁边再开一个本地终端整理脚本。

## 什么时候使用分屏

- 同时查看日志、运行命令、观察服务状态
- 对比生产、测试、本地三个环境的输出
- 在一台服务器上执行操作，另一台服务器上实时观察影响
- 需要让 AI 基于当前激活窗格的输出继续分析

如果只是临时切换不同任务，普通多标签页就够了；如果多个环境需要同时看，分屏更合适。

## 创建分屏

在终端右上角菜单中选择：

- **左右分屏**：在当前窗格旁边打开一个新窗格
- **上下分屏**：在当前窗格下方打开一个新窗格
- **分屏并连接到…**：选择新窗格要连接的目标

普通分屏会继承当前窗格的连接类型。例如当前是生产服务器 SSH，新窗格也会连接到同一类 SSH 环境。

## 分屏并连接到

「分屏并连接到…」适合直接打开另一个环境：

1. 点击终端右上角菜单
2. 选择 **「分屏并连接到…」**
3. 选择方向：左右 或 上下
4. 选择连接目标：
   - **本地终端**
   - 已保存的 **SSH 会话**
5. 点击 **「分屏」**

这样可以在同一个标签页里混合本地终端、生产 SSH、测试 SSH。每个窗格都有独立的连接状态和工作目录。

## 切换和关闭窗格

- **切换窗格**：点击任意窗格即可激活
- **关闭窗格**：在窗格菜单中选择「关闭窗格」
- **快捷键**：分屏和关闭窗格的快捷键可在「设置 → 键盘快捷键」中查看和修改

单个标签页里只剩最后一个窗格时，关闭行为会回到普通标签页逻辑。

## Agent 如何选择窗格

Agent 会围绕当前激活窗格工作：

- 你点击哪个窗格，哪个窗格就是当前操作目标
- AI 分析终端输出时，会优先参考当前激活窗格
- AI 执行命令时，会在当前激活窗格对应的本地或 SSH 环境中运行

如果你想让 AI 操作特定服务器，先点击对应窗格再发指令。

## 典型工作流

### 排查线上问题

1. 左侧打开生产服务器，观察 `journalctl` 或应用日志
2. 右侧打开测试服务器，复现问题并验证修复命令
3. 让 AI 分析当前激活窗格的报错，再切到另一个窗格执行建议

### 本地脚本 + 远程验证

1. 左侧使用本地终端编辑和运行脚本
2. 右侧连接远程服务器，观察脚本对服务的影响
3. 需要时再上下分屏开一个日志窗口

### 多服务器对比

1. 同一个标签页里打开生产、预发、测试三台服务器
2. 分别运行相同的检查命令
3. 让 AI 对比输出差异，定位配置漂移

## 使用建议

- 分屏不要开太多，2-4 个窗格最容易管理
- 给 SSH 会话起清晰名称，避免误操作生产环境
- 在执行有风险命令前，确认当前激活的是正确窗格
- 如果任务完全无关，使用新标签页比继续分屏更清爽

## 设计目标（2026-08-14 壳层重排）

把顶栏里固定的入口和右侧图标群搬到左侧，进行中的工作区不再跟导航挤在同一条顶栏。这是换壳，不改会话、Agent、分屏。

**三条主线**

- **新对话**：任务 / 助手。最近对话列表就是它的「多个」。
- **联络**：和秘书的那一条线，不用 tab。
- **终端**：本机和远程都在这里。壳上不再拆成本机 App 对远程 App；本机 / SSH 只在干活时区分。

待办、关切、觉醒、连接、控制面板收进侧栏底。底栏放秘书（身份名，没有就叫旗鱼），不放用户、不假造账号。没有账号就不做退出登录。

**秘书名下面那行只放低频信息**：平时是版本号——想查的时候知道去哪找，不想查的时候不占注意力。「已觉醒」不写在这里，那是常态，头像上那圈绿边已经说了；只有「未觉醒」才顶上来，因为那是个需要用户去做点什么的状态。

**秘书行右部是秘书的装备位**：连接了多少外部系统（渠道、网关、MCP）常驻显示在这里，一眼能看出几个通了、几个没通，点开就能连接或断开，不必绕进设置。这类信息属于「这位秘书现在有多大本事」——将来加载了多少专业能力（技能）也归这里，是同一类东西。原先钉在右上角的连接入口不再单独存在。

**联络和终端：点侧栏是回这个地方，不是新建。** 有内容就回到上次停下的位置；一个都没有才进空页。「+」放在页里面。

**新建快捷键跟着当前位置走**：在终端里按就是开一个本机终端，在别处按就是回到新对话的空白起点。「在这个地方再来一个」比「不管在哪都给我开助手」更符合直觉；想在任何地方强制开终端，另有一个专门的快捷键。任何入口都不再凭空造出一个不在任何列表里的助手页面——顶栏 Tab 条已经撤了，那种页面没有归属，用户既切不走也找不回。新会话一律进最近对话列表。

**「新对话」是个例外：点它就是开一个新的。** 名字承诺什么就做什么——把正在看的那条对话放下，主区回到空白起点。要回到刚才那条，从最近对话列表里点。它只在主区真是空白起点时高亮；正在看某条对话时，高亮落在列表里那一条，两处不同时亮。因为顶上已经有这个按钮，最近对话的标题行不再重复放「+」。

**终端页**

- 页内 tab 同时挂本机和远程，用图标区分。
- 本机 tab 里再劈一个 SSH 窗格，人还在「终端」，tab 不搬家。
- 主机列表不常驻：只在空页，或点「+」要连远程时出现。
- 一个工作台都没有时落到空页：点侧栏「终端」进来是这样，关掉最后一个终端 tab 也是这样——人还在终端这个地方，只是空了，不该被弹回新对话。
- 从欢迎页或快捷键说「我要连远程」时直接给主机列表，不先绕一道空页——那里的意图已经很明确了。
- 空页要和欢迎页是一家人：同一套卡片和主机块的样子，主机最多铺一屏，多的走「管理主机」，不要把几十台堆成一条长名单。
- **AI 面板的显隐开关放在标签那排的最右边**，且常驻：原先那个「关闭」按钮长在面板自己头上，收起之后开关也跟着没了，只能靠快捷键请回来——能收不能开，是个残缺。开关位置固定，面板开着还是收着都在那儿。
- **桌面界面里不再提供「清空对话」**。它原先只挂在面板顶栏，和收起按钮挤在一起，误触一次就抹掉整段对话；而对联络这条连续的关系线来说，清空更不该是随手能点的动作。要重新开始就开新对话。（远程网页会话是另一套界面，不在此列。）

**侧栏可整块收起**（不是收成图标窄栏）。开关留在标题栏、贴着红绿灯（Windows 在汉堡菜单旁）。有事要点打在开关上，收起时也看得见。开合状态记住，不按页面自动切。

**开合是推拉，不是闪现**。收起时侧栏往边上收拢、内容跟着被裁走，展开时反过来推回来；这套节奏对所有侧栏一视同仁——导航侧栏、主机列表、终端里的 AI 面板都一样。主区为浮起来的窗口控件让出的那点位置也跟着同一档节奏挪，否则一边在滑一边在跳。唯一的例外是用户拖边框改宽度：那时宽度要严格跟着手走，不许有惯性。

**没有标题栏**。固定入口、身份名、版本号都迁走之后，那一行只剩一个开关和一片空白，不值得占满窗口上沿。

取而代之的是「第一排」：**每个面板顶到窗口上沿的那一排，既是它自己的功能行，也是拖窗口的地方**。侧栏顶那排、聊天区那排、产出物面板那排、终端的标签那排，都是如此，不再额外叠一条空条。只有本来就没有第一排的页面（欢迎页、空终端页、待办）才由壳层补一条透明区，纯粹为了窗口还能拖动。

「也是拖窗口的地方」对整排有效，不是只有空条才算：终端的标签那排，标签右边那片空白照样能拖动窗口，标签和按钮本身则各自让出来照常点击。

侧栏收起时，原本挂在侧栏顶上的东西（侧栏开关、Windows 的菜单入口）浮到主区第一排上，该排相应让出位置——侧栏整块没了，它们得有去处。

macOS 上**最左那一排永远要给红绿灯让位**，不管当时最左的是导航侧栏、主机管理面板还是浮起来的窗口控件；主机管理打开时它就是最左的一列，同样算数。让位量按内容区别对待：紧接红绿灯的如果是文字标题，要比放图标时多留一档呼吸，否则看着像贴在红绿灯上。同排的图标与红绿灯还要落在同一条水平中线上——差一两个像素肉眼就看得出来。

Windows 是例外：它的三个窗口按钮是自绘的、比较宽，而产出物面板收窄后很窄，浮上去会压住面板自己的按钮，所以 Windows 保留一条顶条来托住它们。这是平台差异，不是设计倒退。

**首页留气味**：欢迎页仍露出助手 / 本机 / SSH / 关切和最近连接，不要收成一句口号加一个框。

**快捷键的跳转保持现状，不另发明一套。** 新建本机终端仍打开那个工作台；关掉覆盖层、关掉当前工作台、从联络 / 待办 / 正在看的对话退回欢迎页、在欢迎页再按一次则隐藏窗口——这些去向都不改。唯一新增的一站是空终端页：关掉最后一个终端 tab 先停在那里，再按一次才退回欢迎页——和从联络、待办退出去是同一个节奏。

**明确不做**

- 不改会话模型、Hub、分屏、Agent 工具按本机 / SSH 分流。
- 助手不再提升到顶栏；顶栏不再放固定入口和那排图标。
- 不把主机管理做成和终端并列的地方。

## 一、全局快捷键清单

所有快捷键在 `handleGlobalKeydown` 中按以下顺序处理（**有顺序依赖，不可随意调换**）：

| 快捷键 | 默认值 | 行为 | 是否可自定义 |
|---|---|---|---|
| 新建（跟随当前位置） | `Cmd+T`（可改） | 终端地方 → `createTab('local')`；其他地方 → `goToHome()` 回新对话起点。无助手的版本一律开终端 | ✅ |
| 新建本地终端 | `Cmd+Shift+T`（可改） | `terminalStore.createTab('local')` | ✅ |
| ESC | 固定 | 关闭 SSH 凭证侧栏（须让路给模态弹窗） | ❌ |
| Ctrl/Cmd+W | 固定 | 见第二节决策树 | ❌ |
| 分屏横向 | `Cmd+D`（可改） | `splitTerminal('horizontal')`，**仅终端 tab** | ✅ |
| 分屏纵向 | `Cmd+Shift+D`（可改） | `splitTerminal('vertical')`，**仅终端 tab** | ✅ |
| 关闭窗格 | `Cmd+Shift+W`（可改） | 关闭激活分屏窗格，**仅已分屏终端 tab** | ✅ |

**分屏快捷键约束**：`tab.type === 'assistant'` 时整组分屏快捷键不生效（`handleSplitShortcut` 直接 return）。

**Windows Alt 键**：单独按下并松开 Alt（不与其他键组合）→ 弹出汉堡菜单（模拟 Windows 系统菜单栏行为）。全屏 overlay 打开时不响应，避免菜单位置异常。

## 二、Cmd+W（关闭/隐藏）决策树

`handleCloseShortcut` 的完整优先顺序，**从上到下依次判断，命中即止**：

```
1. 有全屏覆盖层（觉醒 / 设置 / 智能巡检）
      └→ 关闭覆盖层，结束

2. 有 activeTab（TabBar 可见 Tab）
   ├─ tab.agentId === '__companion__'（联络常驻 tab，不可关闭）
   │     └→ goToHome()，退回欢迎页，不关窗口
   ├─ tab.type === 'assistant' && !isPromoted && !isRemote
   │     （理论兜底，正常流程不应出现此情况）
   │     └→ 隐藏窗口
   └─ 终端 Tab / 已提升助手 Tab / 其他远程助手 Tab
         └→ closeTab(activeTab.id)，不关窗口

3. 无 activeTab，待办面激活
      └→ goToHome()，退回欢迎页，不关窗口

4. 无 activeTab，空终端页（点侧栏「终端」进来，或刚关掉最后一个终端 tab）
      └→ goToHome()，退回欢迎页，不关窗口

5. 无 activeTab，有 hubFocusedAssistantTabId（Hub 焦点模式）
      └→ goToHome()，退回欢迎页（侧栏保留），不关窗口

6. 无 activeTab，无 Hub 焦点（任务首页 / 欢迎页）
      └→ 隐藏窗口（window.close）；后台 tab 保留，下次打开恢复
```

> 关掉最后一个终端 tab 落在第 4 步（不是直接回欢迎页），所以在终端里连按 Cmd+W 是：关完 tab → 空终端页 → 欢迎页 → 隐藏窗口。

**修改此逻辑时必须保证覆盖层始终第一优先，且所有新增的 Tab 类型都在第 2 步内明确处理。**

## 三、macOS ⌘Q 防误触

主进程检测 ⌘Q 事件后，不立即退出，而是先向渲染进程发送 `quit.onToast` 信号：
- 渲染进程显示顶部 Toast 提示条（`quitToastVisible`）
- 用户**在提示条消失前再次按 ⌘Q** → 主进程才真正执行退出
- 提示条自动消失后，再次按 ⌘Q 重新走同一流程

**目的**：防止用户在终端内操作时误触 ⌘Q 退出整个应用。  
**实现**：`window.electronAPI.quit.onToast` IPC 事件 + `quitToastVisible` ref。

## 四、覆盖层（全屏 UI）优先级

以下覆盖层互斥，打开任意一个后 Cmd+W 只关该覆盖层：

| 覆盖层 | 控制变量 |
|---|---|
| 觉醒（Awaken）| `showAwaken` |
| 设置面板 | `showSettings` |
| 智能巡检 | `showSmartPatrol` |

覆盖层关闭后，主区状态（activeTabId / hubFocusedAssistantTabId）不变。

## 五、退出确认计数

应用退出时（`window.electronAPI.window.requestTerminalCount` IPC），向主进程上报"有意义的开放会话数"：

```
有意义 = agentId !== '__companion__'         // 联络常驻 tab 不可关闭，永不计入
        && ( tab.type !== 'assistant'        // 终端 Tab（local/ssh）
          || tab.isRemote                    // 远程助手 Tab
          || tab.isPromoted                  // 已提升的本地助手 Tab
          || (tab.type === 'assistant'
              && !tab.isRemote
              && !tab.isPromoted
              && tab.agentState?.isRunning) ) // Hub 中正在运行的助手会话
```

- 未提升、未运行的 Hub 会话**不计入**（随时可从历史恢复，无丢失风险）。
- **联络常驻 tab**（`agentId === '__companion__'`，虽 `isRemote=true`）**永不计入**——它不可关闭，否则退出时会恒提示"有 1 个标签未关闭"。

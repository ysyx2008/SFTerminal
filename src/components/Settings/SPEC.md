# 控制面板（设置）

## 设计目标

### 为什么需要这份规范

控制面板有二十多个页面，长期以来各写各的。同一个「卡片」在不同页面里其实是不同的东西，同一个开关有三套互不相干的实现，圆角用过十四种取值、字号用过二十一种。结果有两个：

一是页面之间对不上，用户在设置里连着切两页，会觉得像进了两个软件，业余感就是从这儿来的。

二是任何想统一的努力都会误伤。因为没有共同词汇，一条「给所有卡片加边框」的规则会自动伸手够到那些结构完全不同的页面——有的页面内部本来就套着带边框的盒子，外面再加一圈就成了套娃；有的页面开关是自制的，被同名规则一撞就散架。这两种事都真实发生过。

所以问题不是「有几页没调好」，是**根本没有一套大家共用的基础件**。

### 成功标准

- 用户在设置面板里连续切换任意两页，感觉是同一个软件里的同一个地方
- 同一类东西——卡片、设置行、分组标题、开关、分段选择、表单字段——在所有页面里长得一样、行为一样、间距一样
- 新增一个设置页时，作者不需要、也不应该重新设计这些东西；照着现成的拼即可
- 任何一次统一性改动，都不会让没被改造的页面出问题

### 关键取舍

**基础件是加入制，不是覆盖制。** 一个页面只有在被明确改造时才采用新样式；没改造的页面一行都不会动。宁可让统一来得慢一些，也不接受「改一处、坏一片」。这条是从实际教训里来的，不是洁癖。

**基础件要约束结构，不能只约束外观。** 光有一套样式规范拦不住页面往设置行里塞一个自带边框的盒子，也拦不住有人另起一套开关。所以基础件必须限定里面能放什么，而不是只规定看起来什么样。

**尺寸只能从固定档位里取。** 间距、字号、圆角各自只保留有限几档。如果某处取不到合适的值，那说明设计意图没想清楚，而不是应该新增一档。

**不追求一次推平。** 先把基础件立住、做出样板页，其余页面逐步迁移。中途停下也不倒退——基础件在那儿，此后新写的页面自然就是规范的。

### 明确不做的事

- **不为了统一而牺牲页面本来就对的交互。** 一个整块可点击的控件，不能因为「要跟普通设置行长得一样」就退化成一行摆设。视觉一致服从于交互正确。
- **不动设置项本身的功能与含义。** 这轮只解决「长什么样、怎么摆」，不改任何设置的行为，也不删改设置项。
- **不为个别主题打专用补丁。** 一个视觉问题如果只在某套主题下修好，那它在其余主题下多半还坏着——历史上就是这么埋下十套主题卡片凹陷的。要么在所有主题下都成立，要么不算修好。

## 行为契约

- 面板内容不随窗口宽度无限拉伸。项目名与它对应的控件，始终保持在一眼能关联起来的距离内。
- 卡片在任何一套主题配色下都必须与页面底色分得开。不允许出现「看不见卡片」或「卡片陷进去」。
- 描述性文字在任何主题下都要能正常阅读，不能暗到需要凑近看。
- 开关、分段选择等控件可以用键盘操作，并且有看得见的焦点提示。
- 分组标题在视觉上必须明显退后于设置项名称，让用户一眼能分出「这是一组」和「这是一项」。

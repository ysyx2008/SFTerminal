# Conversation 模块 SPEC

> Last verified: 2026-08-19

## 职责

会话领域模型：`Conversation` 聚合根、策略表、`Companion` 关系线、transcript 切分。

## 设计目标

### 新对话何时进历史

- **问题**：以前新对话要等第一次任务跑完才写入历史。进行中崩溃、切走再回来，这条对话会丢或从侧栏消失。
- **成功标准**：用户发出第一条消息后，这条对话就进历史；之后任务进行中持续记下进度，中途崩溃最多丢掉没写完的那一轮，整段对话还在。
- **关键取舍**：认「已经开了头的会话」，不认「已经跑完的历史」。
- **明确不做**：只点了新对话、还没说话，不进历史（避免一堆空白条目）。联络 / 关切 / 唤醒各自原来的进出规则不变。

### 侧栏标题跟着聊，但手改过的不碰（2026-08-17）

- **问题**：标题只根据用户第一句话生成。聊着聊着事情变了，侧栏还停在开头那句，不好认。
- **成功标准**：新对话先用第一句话出个标题，方便马上出现在侧栏。之后每完整说完三轮（一轮 = 用户发一条并跑完，中途追加不算），趁着刚聊完再根据整段对话重写一次。人手改过的名字，之后不再自动改。新标题和旧的几乎一样时，侧栏不动。
- **关键取舍**：按固定轮次刷新，不猜「话题换没换」。标题是路标，不是实时摘要。
- **明确不做**：联络、关切、唤醒不跟这套。不把「请起个标题」写进用户看得见的对话。说不清是不是手改的旧记录，按可以自动更新处理。

### 联络时间线不被主动提醒挤掉（2026-08-19）

- **问题**：心跳、关切每次主动找人都会单独记一条。联络页按「最近几条记录」拼时间线时，这些提醒把真对话挤出去，打开只剩几条催办，昨天聊过的话看不见。启动时如果提醒已经先到了，整段历史还会干脆不恢复。
- **成功标准**：打开联络能看到最近大约十段真对话，夹在中间的主动提醒还在。提醒再多也不占真对话的名额。启动时已经弹出的提醒不会挡住历史；接上之后提醒还在、不重复。
- **关键取舍**：名额按「真的聊过」算，不按「落盘了几条」算。
- **明确不做**：不把全部联络历史一次铺开。不改任务侧栏。不删已经记下的提醒。

## 从这里创建任务（companion → task）

用户在联络里点某条消息「从这里创建任务」时，设计意图是：

**以当前这条为终点，倒序往前取一段上下文；不要带上这条之后的消息。**

往前取时：
- 按用户对话扩窗（间隔约 6 小时内、最多约 10 段）；主动通知不当切断点。
- 窗口内的主动通知要带上；紧挨窗口第一条用户话之前的那条通知也要带上（常见「通知 → 用户接着回」）。
- 若点的就是主动通知本身，只带这一条。

实现入口：`Companion.extractTaskWithLiveOverlay` → `Conversation.extractTaskFromRecords`。
与 task 的「另开一聊」（从头截到第 N 个）不是同一套语义。

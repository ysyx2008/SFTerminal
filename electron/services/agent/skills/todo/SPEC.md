 * ## 设计目标
 *
 * 桌面待办面板要像秘书一样**综合权衡**后再提示，而不是只靠 priority 标签：
 *
 * - **已逾期最急**：已经过了截止日期的事项排在活跃列表最前，视觉热度至少与即将到期同级（警戒红），不能看起来比即将到期还轻
 * - **即将到期单独成区**（催在逾期前）：进入条件（任一即可）：本地日历「今天」截止、**绝对剩余 ≤ 48 小时**、或剩余时间占比 ≤ 20%。分区互斥：符合条件的活跃项只出现在「即将到期」，不重复出现在进行中/待办
 * - **双通道不抢戏**：
 *   - **标题色** = 综合关注度：重要度（`priority`）× 时限档 × 陈旧度（`createdAt`，轻量补洞）；「今天」主要靠分区 + 截止芯片警示色突出，不为「剩 N 天」再拆多档标题色
 *   - **行背景进度** = 有 `dueDate` 时按**绝对剩余时间**画条（见下），**不是**「预留时间用掉多少」；逾期/无截止不画条
 * - **行进度条语义（绝对剩余）**：用户扫一眼要分清「明天要交」与「两周后的事」——今天建、明天交的任务不能因比例≈100% 而看起来从容。条长 = `min(1, remainingMs / 14d)`（14 天封顶满条）；颜色复用项目现成的**跨主题固定三档强弱阶梯**（`main.css` 已有、专为红→橙→绿三档强弱设计，永远是 Tailwind 原色不随主题降饱和），真正换色相而非同色调深浅或透明度：
 *   - 剩 ≤ 2 天 → `--brand-alert`（红，紧急）
 *   - 剩 ≤ 7 天 → `--brand-caution`（橙，该关注了）
 *   - 剩 > 7 天 → `--brand-vital`（绿，从容）
 *   均以低浓度 `color-mix(... 14–16%, transparent)` 浅透叠底，不做纯色实块
 *   **Hover**：速览卡**跟随鼠标**瞬时出现（`TodoRowHoverTip.vue`，`Teleport` 到 body + `position: fixed`）；贴光标右下，用 `ResizeObserver` 测真实渲染尺寸做视口翻折/夹取（**不用固定宽高估算**——卡片内容量随条目差异很大，估算值必然与真实尺寸脱节导致翻转判断错误）。内容：标题（≤2 行）+ 备注摘要（≤3 行，≤200 字）、状态/优先级徽标、截止日期 + 色点（复用红/橙/绿三档）+ 剩余文案、标签、创建/更新/完成时间；有进度条时附条长含义。完成/删除按钮悬停时隐藏速览。紧急档判定 (`dueUrgencyTier`) 与进度条颜色共用同一函数，不重复散落阈值。目标是多数情况不用点开右侧详情
 * - **列表排序（面板）**：分区顺序为 已逾期 → 即将到期 → 进行中 → 待办 → 已完成；区内只按重要度 `urgent > high > normal > low`，同档按创建时间
 * - **颜色（跟主题走）**：已逾期与即将到期的分区/芯片/`strong|critical` 标题都用 `--brand-alert`；高优/`medium|mild` 标题用 `--accent-warning`；普通标题 `--text-primary`；进度条见上档；禁止硬编码 hex
 * - **陈旧度只补洞**：活跃、无即将到期/逾期时，high/urgent 本就轻度着色；创建超过约 7 天再上浮一档（最高 medium），不得到 critical / 不得盖过「已逾期 / 即将到期」
 * - **完成/取消**：弱化划线，忽略关注度着色与进度条
 * - **Tab 注意力**：有尚未看过的逾期时 Tab 闪烁；打开待办面即确认当前逾期集合，之后仅新增逾期再闪（持续忽视由秘书主动通知兜底）
 * - **本版范围（面板排序）**：面板展示与面板内排序；不改后端列表排序、心跳 `render.ts`
 *
 * ## 设计目标：把一条待办交给秘书（右键「帮我办」/「分配时间」）
 *
 * 待办面板每一行都能右键交办，只有两项：**帮我办**、**分配时间**。已完成/已取消的条目上两项都不可用。
 *
 * - **「帮我办」的首要价值是省搬运，不是保证办成**：用户不必再把标题、备注、截止、标签手动复制进输入框。右键即开一个新任务会话，把这条待办**原文完整搬过去**——不摘要、不改写（摘要就是丢信息，等于白省了搬运）。派活前**不弹任何补充信息的表单**，要补充直接在会话里说。开完直接切到该会话，用户能看着办、随时插话或打断。
 * - **状态归 Agent 判断**：右键交办不由程序改待办状态（不预置进行中，也不代为标完成）。怎么办、办到哪、要不要标完成，交给模型。
 * - **「分配时间」以已关联日历账户为前提**：未关联时该项置灰、悬停说明原因，点击直达设置的日历页，不用弹窗解释。
 * - **时长走二级菜单**：30 分钟 / 1 小时 / 2 小时 / 半天（半天按 4 小时）。选中的时长作为信息交给新会话，不另附排期说明书。
 * - **事项日志（这件事的流水）**：待办上按时间累积一条流水，记两类事——「安排了哪段时间做」（含日历事件出处，便于日后对账）与「某次交办推进到哪儿」。目的是日后能统计一件事总共占了多少时间、以及回头看它为什么拖了三周。同一件事经常要排好几次，故**不用**可被覆盖的单一「计划时间」字段。安排过的时间在悬停速览与右侧详情里看得见（列表行不加负担），避免重复安排。
 * - **不做**：派活前的上下文完整度检测；待办与日历双向同步（日程被用户手工改期/删除不反向同步，只留出处供日后对账）；往日志里记实际耗时
 *
 * ## 设计目标：待办的出处（这条哪来的）
 *
 * 备注只装得下写待办那一刻想到的东西。出处负责**指路**——交办时把「去哪儿能找回原始上下文」一并交给秘书，它自己决定要不要翻。
 *
 * - **出处是指路，不是复制**：记的是某次对话、某封邮件、某个文件、某个网址，各配一句人话说明。**不把原文抄进来**，抄进来就成了第二份会过期的备注。
 * - **「来自哪次对话」由程序自动记**：待办被创建的那一刻本就发生在某次会话里，创建时直接把这次会话记成出处。不靠模型自觉带上。
 * - **其它类型的出处由 Agent 显式带**：这条是从哪封邮件、哪个文件、哪个网页生出来的，只有它知道。用户在面板手敲的待办没有出处，空着即可。
 * - **出处可以陆续补充**：办事过程中发现新材料可以再添。本版不提供删除（面板上没有编辑入口）。
 * - **交办时把出处一并交给 Agent**，不另附「该怎么用出处」的说明书。
 * - **失效必须无所谓**：会话被清理、文件被删、邮件被归档，都会让出处指向不存在的东西。失效不报错、不影响待办本身。
 * - **出处与事项日志分开**：出处是「从哪来、材料在哪」，指向外部、可陆续补充；日志是「发生过什么」，只追加。混成一条流水的话，日后清理失效材料会把历史记录一起搅乱。
 * - **不做**：自动关联猜测（不扫用户的文件或邮件替他找「可能相关的材料」，只记写入时明确知道的）；面板上点出处跳回原处（本版只在悬停速览与详情里看得见，跳转下一版再说）

 * ## 职责

 * ## 真相源入口（OOP）
 *
 * - **`TodoService`**（[`store.ts`](./store.ts)）+ `getTodoService()`：主进程完整门面
 * - 公开表面：`load` / `save` / `mutate` / `list` / `create` / `update` / `complete` / `delete` / `countOverdue` / `onChanged`
 * - `TodoItem` 仍是 `@sailfish/shared-types` **interface**（IPC / JSON 线格式），不做实体类
 * - [`api.ts`](./api.ts) 为 IPC/CLI 薄 facade（`listTodos` → `getTodoService().list` 等）
 *
 * ## 存储
 *
 * - 路径：`{userData}/agent-workspace/TODO.json`
 * - Schema：`@sailfish/shared-types` 的 `TodoItem` / `TodoStoreData`
 * - **勿**将 `TODO.json` 加入文件工具免确认白名单；仅技能 / 面板 IPC 可写
 *
 * ## 工具
 *
 * | 工具 | 用途 |
 * |---|---|
 * | `todo_list` | 列表；过滤/排序；默认排除 completed/cancelled |
 * | `todo_create` | 新建；自动 id/createdAt/updatedAt |
 * | `todo_update` | 改字段与 status；管 completedAt；可追加一条日志或出处 |
 * | `todo_complete` | 快捷标记完成 |
 * | `todo_delete` | 彻底删除 |
 *
 * ### 状态机
 *
 * - `todo_update` 可改 `status`（含取消、重新打开）
 * - 进入 `completed` → 写 `completedAt`
 * - 离开 `completed` → 清空 `completedAt`
 * - **`createdAt` 不可改**
 *
 * ## 桌面待办面板
 *
 * - 入口：TabBar 固定区，在**联络右侧**、新建按钮之前（`[… 联络] [待办] [+]`）
 * - 形态：伪 Tab（`terminalStore.todosActive`），非 Agent / Workbench 会话
 * - IPC：`todo:list` / `create` / `update` / `complete` / `delete` / `countOverdue`；写入后广播 `todo:changed`
 * - API：`skills/todo/api.ts` → `TodoService`（与 Agent 工具共用单例与写队列）
 * - UI：`src/components/Todo/TodoPanel.vue` — 轻量 CRUD（列表/筛选、新建标题+截止、完成/重开/删除）；标题色/行进度见上方「设计目标」

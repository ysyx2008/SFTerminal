# 2026-08-23 功能完整的子智能体 — 实现方案

> 2026-08-23。**未完成。** 本文只谈怎么落地，供确认后编码。确认后把稳定取舍写进 `electron/services/agent/SPEC.md` 和 `src/components/AIPANEL_SPEC.md`，再动手。

对标的是 Codex 的协作模型，不是抄它的界面和「替我审批」。旗鱼自己的两条硬规矩已经谈过：

1. **伙计可以动手，但不能找你签字。** 确认是独占的前台，只走主人。
2. **伙计的过程是过程。** 折叠行收进去；不另开一条对话。

## 心智：功能完整指什么

子智能体是这场任务里**还活着的同事**，不是一次外包函数。

它能干主人在本机/助手里能干的活：读、写、改、搜、跑普通命令、用不必问人的技能。主人只需说「去审登录那块」，不必写一份自包含说明书。

它不能顶替主人：

- 不能找用户签字、提问、要密码
- 不能主动联系用户、建关切
- 不能再派孙智能体
- 不能改计划、开终端窗格
- 不能做会改「用户对外的世界」的事（发信、改日程等）——这些卡住了交给主人

和 Codex 的对照：

| Codex | 旗鱼 |
|---|---|
| 子会话是一等公民，用户可切进去 | 过程，收在折叠行里；点开父级那一行才能核对 |
| 子智能体可再派活、可互相传话 | 只派一层 |
| 审批跟父级同一套，或「替我审批」 | 子智能体没有确认通道；要拍板只走主人 |
| 派出立刻回来，做完敲门 | 同样 |

## 生命周期

1. 主人调用 `dispatch_agents`（可一次多个），立刻拿到每个伙计的名字，自己继续干。
2. 伙计是一台真正的旗鱼 Agent，工具面收窄、没有确认通道。
3. 伙计做完、失败、被打断：往主人的待处理消息里敲一声（带名字和结果/卡住原因）。主人还在跑就接着看；若模型刚说完话、本会收工，只要还有活着的伙计或刚敲门的结果，就继续转。
4. 主人可 `followup_agent` 再交代、`interrupt_agent` 叫停、`wait_agents` 可选地等一会儿（带超时，不该死等）。
5. 用户点停止、或这场任务结束：所有伙计一起停。不跨任务复活，不进历史侧栏。

当年异步派出结果丢失，就是因为主人收工了没人接。这次收工条件改成：**没有待处理消息，且没有活着的伙计**。

## 上下文怎么带

默认带着走，但先清洗（Codex 的 `keep_forked_rollout_item`）：

- 留下：用户说的话、助手说出口的最终答复
- 剥掉：所有工具调用、工具结果、思考块、派遣记录

再拼上主人这次的任务说明。伙计看不见 `dispatch_agents` / `talk_to_user` 的先例，不会去模仿。

不提供「完全不带上下文」的默认项——那会退回现在「必须写自包含说明书」的别扭。

## 工具面（功能完整的边界）

取消 `read` / `write` 两档。旧值（explore / research / edit）忽略，不再映射。

**伙计没有的（从清单拿掉，硬调也拦）：**

- 身份：`talk_to_user`、`ask_user`、关切工具、再派伙计、`plan`、窗格/终端入座
- 要问人的：任何会走确认框的能力（发信、改日程、高危命令、插件要求审批的）
- 规划锁开着时：与主人同一套「只能探环境 + 写草稿」

**伙计有的：** 读/写/改本机文件、普通命令、搜索、知识库、网页、不必问人的技能（浏览、表格、文档等）。宽松模式下本来就不弹窗的写和普通命令，伙计可以直接做。

高危命令：清单里若仍露出 `exec`，运行时按现有 `isSubAgentBlocked` 拒绝，并让伙计把「被拦了、原命令是什么」写进最终汇报。主人决定要不要自己做（那时才可能问你）。

## 呈现（折叠已经判过）

- `dispatch_agents` 卡带着 `subAgents`：**仍是过程**，默认收进折叠行。不改 `isPinnedProcessStep`。
- 点开那一行：能看到每个伙计的名字、在忙/做完/卡住、它的步骤。这就是「想核对再看」，不另做切会话。
- 要你拍板的卡仍在外面——只有主人会出这种卡。
- 主人等伙计、自己没在写新思考时：折叠行必须还活着（走秒 + 一句「几个人在并行」之类），避免以为卡住。不为伙计另写模型摘要。

严格模式仍然整段不折叠，派遣卡本来就在流里。

## 不做

- 不学 Codex 的「替我审批」
- 不给用户切进伙计自己的对话（第二条对话）
- 不让伙计再派孙智能体、不让伙计互相传话
- 不把伙计做成最近对话里的一条
- 不在 SSH 远程会话里新开放（仍限本机 / 助手，与现在一致）
- 不为折叠另写摘要、不改「子任务进度是过程」

## 任务拆解

1. **SPEC 落盘**  
   把上文「心智 / 确认 / 折叠 / 不做」写成用户语言写进两个 SPEC。验收：每句能说能验，无类名。

2. **父循环：有伙计就不能收工**  
   活着的伙计集合 + 完成敲门进 `pendingUserMessages`。验收：单测模拟「派出后模型不再调工具、伙计稍后完成」——主人必须接到结果再收工；用户停止则伙计全停。这是当年异步 bug 的对症验收。

3. **真实例 + 清洗上下文**  
   伙计用同一套 Agent 循环；开局是清洗后的对话 + 任务说明。验收：历史里含 `dispatch_agents` / `plan` 的父对话，伙计的 messages 里没有这些工具调用；伙计调不存在的工具会被清单挡住。

4. **工具面收窄**  
   身份 / 要问人 / 对外打扰从清单拿掉；取消 read/write。验收：伙计的工具列表不含 `talk_to_user` / `ask_user` / `dispatch_agents` / 发信；含 `read_file` / `edit_file` / `exec`。规划锁开着时与主人同一把锁。

5. **异步派出 + 再交代 / 等待 / 打断**  
   `dispatch_agents` 立刻返回名字；其余三个工具。验收：一次派出两个，主人在伙计完成前能再调别的工具；`followup_agent` 能把补充送进还活着的那个；`interrupt_agent` 后状态为已打断；`wait_agents` 超时返回、有结果则提前结束。

6. **派遣卡 + 折叠行还活着**  
   卡上名字/状态/步骤；等伙计时折叠行走秒。验收：过程折叠开着时派遣不钉在外面；展开看得到进度；严格模式卡在流里。

7. **回归**  
   `bash electron/cli/test-cli.sh --no-ai`；补子智能体单测（收工、清洗、工具面、停止级联）。

## 怎么验收（产品）

1. 主人说「同时查 A 和 B」，两个伙计立刻开工，主人还能继续说话或干别的，不必干等。
2. 伙计看得见这场对话在讲什么，主人不用把路径和目标再写一遍。
3. 伙计改普通文件、跑普通命令可以；发信、高危命令、问用户——做不到，会告诉主人。
4. 默认界面仍是一行过程；点开能核对伙计；不会多出一条对话或一堆确认框。
5. 点停止，伙计一起停。
6. 规划锁开着，伙计也改不了用户的世界。

# 2026-08-22 任务规划模式 — 实现方案

> 2026-08-22。**未完成。** 设计目标已写入 `electron/services/agent/SPEC.md`。本文只谈怎么落地，供确认后编码。

## 心智

任务会话上一个开关。开 = 这场任务锁在规划里；关 = 恢复动手。不是新的会话种类。

## 改哪些模块

| 模块 | 做什么 |
|---|---|
| 共享类型 + 会话落盘 | 任务记录上增加「规划中」状态，恢复/续聊带着走 |
| Agent 工具面 | 规划中只露出探环境 + 提问 + 草稿区可写；动手类工具整份拿掉 |
| 执行拦截 | 工具面漏了也拦：写路径不在草稿区、会改世界的命令、对外打扰，一律拒绝 |
| 输入框 | 任务会话输入框旁一个开关；拨关不自动开跑 |
| 文案 | 中英同步 |

预计动：共享类型、会话聚合根/落盘、工具清单与执行拦截、Composer、i18n。不碰联络/关切/唤醒策略表。

## 怎么锁（两道，缺一不可）

1. **工具面**：规划中，动手类能力从清单里拿掉。跟「无人值守时不给提问」同一条原则——环境里没有的能力不假装存在。
2. **执行拦截**：仍可能漏（技能中途加载、模型硬调、复合命令）。写文件只放行草稿区；命令用现有风险审计，会改世界的拒；发信/建日程/建关切/对外说话拒。子任务只允许只读那种。

开关拨动会换工具清单，下一轮前缀缓存会 miss 一次。用户主动拨开关，可接受。

给模型的说明只陈述事实：「这场任务现在锁在规划里，不能改用户的世界；可以探环境、可以写草稿。」不教它交什么样的方案。这条说明随开关变，不写进整场对话不变的那截常驻说明，以免每轮弄脏前缀。

## 草稿

沿用已有的工作区草稿区（scratch）。规划中唯一允许的写落在这里。不强制写、不规定文件名和格式。草稿区本就会过期清理；用户要长期留着，是关掉规划、真正动手之后的事。

## 开关时机

- 拨开：若正在跑，当前这一轮立刻按规划锁住（正在改世界的动作能停则停，停不了的这次做完，下一刀拦住）。
- 拨关：只改状态，不新开一轮。等用户再说一句才动手。

## 不做

- 不新造「方案」专用工具，不规定 `<proposed_plan>` 一类格式
- 不改现有执行清单工具的职责
- 不做「以后不再问」批准入口（另议）
- 第一期不做 IM/Web 上的这把开关（那些入口没有任务输入框；任务本身的锁仍生效，从桌面拨过的状态继续有效）

## 怎么验收

1. 新任务默认能动手。拨开后写桌面上的文件、发邮件、建关切，必须被拒；读文件、搜索、看日历、往草稿区写，必须能做。
2. 对话里说「开始做」而开关仍开着，仍然不能动手。
3. 拨关后不自动出现新的执行步骤；再发一句才会动手。
4. 关掉再打开同一条任务，开关状态还在。
5. 联络/关切界面上看不到这把开关。
6. `bash electron/cli/test-cli.sh --no-ai`，并补规划锁的拦截用例。

# 同一场对话：先带原文，满了才交接（2026-09-04）

> 2026-09-04。**已完成。** 设计目标已写入 `electron/services/agent/SPEC.md`「同一场对话先带原文，窗口满了才交接」。本文是实现方案。

## 1. 要改什么

不再按远近把同一场收成提要 / 一句话，也不另做一套「只收过程」的五档。和 Codex 一样，只有两态：

- 窗口没满：整场原样带着（含过程）。
- 窗口满了：走已有交接，原文可以不再全留。

## 2. 两态

| 状态 | 带着什么 |
|---|---|
| 还没满 / 还没交接过 | 原文：用户原话 + 中间过程 + 实际收场 |
| 已经交接过 | 最近一次检查点（交接正文 + 检查点里还留着的话） |

收场必须按实际：做成了留最后交代；被停、失败、还在等拍板，照实留。没有正常总结也不许整轮消失，不许编造成功收场。

## 3. 预算

先扣：常驻说明 + 工具清单 + 本轮预留 + 交接预留。**扣完后的剩余全部给这场历史**。

装法：

1. 从新到旧放入每一轮原文（单条过长先单独收这一条）。
2. 装不下的更早整轮进可取回归档，不砍成标题。
3. 工作记忆不再用「最多 50 轮」扔掉更早原文。上限改为窗口 / 交接。
4. 历史图片不整场重塞；文字和路径留下。热路径 / 检查点前缀原样带着已接受的图。

## 4. 耗尽边界

- **热路径（还在这场）**：窗口快满 → 已有交接。不新做交接。
- **冷启动（重开 / 回收后再点开）**：
  - **有检查点**：从最近一次交接检查点接着。不把已交过的原文再展开。
  - **没有检查点**：从完整记录原样重装。原文本身仍超窗：从近往远尽量多留完整原文，更早整轮进可取回归档，**不**砍成标题。

## 5. 改哪些文件

- `electron/services/agent/context-builder.ts`：冷启动装原文，取消五档降级；预算（取消 40% 封顶）

- `electron/services/agent/__tests__/context-builder.test.ts` 及预算 / 冷启动 / 检查点恢复相关测试

## 6.5 Codex 怎么做（对照 `/Users/yushen/Source/codex`）

Codex **没有**五档过程压缩。只有两态：

- 窗口没满：整场原样带着（含过程）。
- 窗口满了 / 用户手动 compact：让模型写一份交接，**替换**当前工作上下文。替换后留下：从新到旧尽量多的**用户原话**（合计大约两万 token，超了就截最旧的那一条）+ **一份交接**。工具过程和它自己的回复原文都不再留，靠交接承接。图只留文字，不重塞。

交接会写成检查点，跟对话一起记住。重开从最近一次检查点接着，不把压掉的原文再展开。压的时候写交接自己也超窗，就从最旧的历史往下丢，保住新的。他们会提醒：压太多次不如新开一场。

本次按这套两态做。不另留五档给「还没压过的重开」。

## 7. 已定

1. 和 Codex 一样：原文，或交接。没有第三套按远近收过程的档位。
2. 交接跟对话一起记住。
3. 重开从最近一次检查点接着，不把已交原文再展开。无检查点才原文重装。
4. 压过之后，路径和失败写进交接，不在地板上另留一行产物。
5. 同一场联络续聊同一套；条数上限按窗口/交接。
6. 单条过长先收用户贴进来的大段，再收它写的长报告；路径尽量保住。

## 8. 验收

- 重开一场多轮对话（含较早写过的文件），续聊「打开你前面写的那个」时，它能从原文对上，不必只靠搜文件 / 搜历史。
- 窗口未满时，较早轮次的过程也还在，不只剩问答。
- 热路径把窗口堆满时，仍走已有交接，不出现按远近收过程或砍首句。
- 唤醒行为不在本次改。

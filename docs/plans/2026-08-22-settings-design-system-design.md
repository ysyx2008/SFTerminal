`src/components/common/` 现有 3 个组件（ConfirmDialog / Toast / UpdateNotifyCard），前端从未有过基础件层。

## 2. 为什么是组件而不是 CSS 类

前序工作里尝试过「共享 CSS 类」路线，失败了两次，原因同一个：

1. **主题页开关散架** —— 共享规则挂在 `.toggle-slider` 上，而该页开关外层不是 `.toggle-switch`、滑块用 `::after`，同名不同构，一撞就错位。
2. **IM 页三层边框** —— 共享规则给所有 `.settings-section` 加边框，而该页卡片内部本就套着两层自带边框的盒子。

根因是 **CSS 类选择器是覆盖制的**：写下一条规则，它就自动作用于所有碰巧用了这个名字的 DOM，不管结构是否匹配。在一个 107 种类名、结构各异的代码库里，这等于每条共享规则都是一次盲改。

**组件是加入制的**：页面不 import 就不受影响，爆炸半径为零。更关键的是组件通过插槽约束结构——`.setting-row` 拦不住有人往里塞带边框的盒子，`<SettingRow>` 可以。这正对应 SPEC 里「基础件要约束结构，不能只约束外观」。

## 3. 三层结构

### 3.1 令牌层（词汇）

在 `main.css` 的基础 `:root` 中定义，与既有 `--bg-*` / `--text-*` 同处：

```css
/* 间距：68 种收敛为 6 档 */
--sp-1: 4px;   --sp-2: 8px;   --sp-3: 12px;
--sp-4: 16px;  --sp-5: 24px;  --sp-6: 32px;

/* 圆角：14 种收敛为 3 档 + 全圆 */
--radius-sm: 6px;    /* 控件：按钮、输入框、分段项 */
--radius-md: 10px;   /* 容器：卡片、面板 */
--radius-full: 999px;

/* 字号：21 种收敛为 5 个角色 */
--fs-title: 15px;    /* 页面级标题 */
--fs-label: 13px;    /* 设置项名 */
--fs-body: 13px;     /* 正文 */
--fs-desc: 12px;     /* 描述 */
--fs-meta: 11px;     /* 分组标签、徽标 */
```

字号定义为**角色**而非尺寸（`--fs-desc` 而非 `--fs-12`），这样将来整体调整字号不需要改调用处。

### 3.2 基础件层（组件）

新建 `src/components/Settings/kit/`，八个组件：

| 组件 | 职责 | 插槽约束 |
|---|---|---|
| `SettingsPage` | 页面根容器，负责限宽居中与分组间距 | 只接受 `SettingsGroup` |
| `SettingsGroup` | 一个分组 = 标题 + 卡片 | 标题为 prop；内容只接受行类组件 |
| `SettingRow` | 一行设置：左侧名称+描述，右侧控件 | `label`/`desc` 为 prop，默认插槽只放控件 |
| `SettingToggle` | 开关（含键盘焦点环） | 无插槽 |
| `SettingSegmented` | 分段选择 | options 为 prop |
| `SettingField` | 表单字段：标签在上、输入在下 | 默认插槽放输入控件 |
| `SettingList` / `SettingListItem` | 可增删的列表（账号、服务器、插件等） | 列表项内容 + 操作区插槽 |
| `SettingEmpty` | 空状态 | 图标/文案 prop |

设计要点：

- `SettingRow` 的 `label` / `desc` 走 prop 而非插槽，杜绝页面自己写标题结构（这是 107 个类名的来源之一）
- 卡片边框由 `SettingsGroup` 统一决定；因为它的内容只能是行类组件，不会出现嵌套盒子，所以可以安全加边框——这正是前序失败的反面
- 组件内部只能使用 §3.1 的令牌，不允许出现裸数值。加 stylelint 规则强制（见 §5）

### 3.3 迁移层

一页一页重写。每迁移一页，删掉该页 scoped 样式里被基础件接管的部分。目标是 1569 条规则大幅塌缩，剩下的应当只有该页真正特有的东西（如主题预览卡、Token 统计图表）。

### 阶段 2 — 基础件层 ✅ 首批已完成

已实现 7 个：`SettingsPage` / `SettingsGroup` / `SettingRow` / `SettingToggle` / `SettingSegmented` / `SettingField` / `SettingHelp`。

实施调整：未按原计划一次性铺满 8 个。`SettingList` / `SettingListItem` / `SettingEmpty` 改为等样板页真正需要时再补——先造后用容易造出没人用的抽象。同理未做独立预览页，直接用样板页验证。事实证明这个判断对了：三页样板跑下来，原计划的三个列表类组件一个也没用上（模型页与 IM 页的列表项都带强域特征，抽象出来只会是个空壳），反倒压出了计划外的 `SettingHelp`。

设计决策（实现中确定，值得记）：

- **组标题移到卡片外**当眉标，卡片里只剩设置项。这是纯 CSS 路线做不到、当时被迫放弃的一点（要改十几个页面的模板结构），组件化后自然解决。
- **`SettingsGroup` 的卡片可以安全加边框**——它的内容只应是行类组件，不会再套带边框的盒子。这正是前序 IM 页三层框问题的反面。
- **`SettingToggle` 不用 `<label>` 包裹**，改由透明 input 铺满接收点击。因为整行可点的 `SettingRow` 本身渲染为 `label`，而 label 不能嵌套。
- **名称/描述走 prop 而非插槽**，堵住"页面自己写标题结构"这条路——它是 107 个容器类名的来源之一。

#### 样板页压出来的基础件缺口（均已补）

| 缺口 | 来源 | 处置 |
|---|---|---|
| 分组标题行只能放标题 | 模型页标题行带说明 + 「添加」按钮；绝大多数页同构 | `SettingsGroup` 增 `desc` prop 与 `#actions` 插槽 |
| 卡片强制存在 | 模型页/IM 页的内容本身就是一排自带边框的盒子，外面再套卡片等于多一圈空框 | `SettingsGroup` 增 `variant="plain"` |
| 分段项无危险态 | IM「自由模式」= 放弃逐条确认，原实现用警示红 | `SettingSegmented` 选项增 `tone: 'danger'` |
| 无就近帮助 | IM 底部把 6 个平台的配置步骤全铺在页面上 | 新增 `SettingHelp` 浮层基础件 |

#### 迁移中修正的既有设计问题

- **卡片套卡片**：三页都有「外层卡片 + 内层自带边框的盒子」，外层不提供任何信息。IM 页的「过程消息」甚至套了两层样式完全相同的盒子。一律去掉外层，内层改用卡片底色自我抬升
- **重复真相源**：IM 每个平台卡里已有一套简版配置步骤，页面底部又铺了一套详版，且两套对不上——飞书简版 4 步、详版 8 步，缺的权限开通/事件订阅/发布应用都是连接必需的。删简版留详版并收进浮层；微信走扫码无详版，其简版是唯一一份，保留
- **一项一卡**：模型页两个自动切换开关各占一整张卡片，间距比内容还宽，合为一组

#### 令牌档位的压力测试结论

三页迁移未新增任何间距/圆角/字号档位，原定档位够用。唯一的尺寸争议是分段项最小宽度——曾按「按内容收敛」去掉，实测不同字数的档位宽窄不一更难看，最终保留 `min-width: 76px` 以统一宽度。

## 5. 防回潮

规范建立后最大的风险是慢慢又长回去。两道闸：

- **stylelint 规则**：`src/components/Settings/kit/` 下禁止裸数值的 `padding` / `margin` / `gap` / `border-radius` / `font-size`，只允许 `var(--sp-*)` 等令牌
- **SPEC 约束**：`src/components/Settings/SPEC.md` 已写明「新增设置页时作者不需要也不应该重新设计这些东西」，作为 review 依据

## 6. 已知风险

| 风险 | 应对 |
|---|---|
| 八个基础件覆盖不了某些复杂页面 | 阶段 3 特意选了最乱的 IM 页来试；覆盖不了就补基础件，而不是让页面绕过去自己写 |
| 迁移中途停摆，形成新旧两套并存 | 加入制天然容忍并存——未迁移页不受影响。SPEC 已声明「中途停下也不倒退」 |
| 组件 prop 化后灵活性下降 | 优先用具名插槽开口子，而不是回退到「随便传 class」 |
| 令牌档位定得不合适，迁移时频繁想加档 | 阶段 3 三页样板正是档位的压力测试；确需增档在此阶段一次性定完，之后冻结 |

# 2026-08-26 独立助手操作主机后更新对应主机记忆

已完成

## 要什么

独立助手开了真终端、对某台或多台机器动手之后，那些机器自己的记忆也要更新。只聊天仍只写个人记忆。下次从终端页打开那台机器，秘书记得这次攒下的、属于那台的事实。

设计目标已写入 `electron/services/agent/SPEC.md`。

## 现状

- 任务做完后，L2 知识文档只写进**一份** `contextId`：`run.context.hostId`，缺省才是 `personal`。
- 前端给助手 tab 算主机身份时，凡不是远程 tab 一律当成 `local`。所以助手现在会把事实写进**本机**那份，和本机终端共用。
- 身份在发消息时拍死，中途开了远程窗也不会改。
- 窗格工具执行时已经能解析目标窗格（`pane_id` → pty），后端也能知道这扇窗是本机还是 SSH，以及 SSH 的账号与地址。收工写记忆时没用上。

## 准确性（怎么才算认准了）

准的只有一件事：**这扇窗当初打开的是哪条连接**。提示符、窗里再 `ssh`、用户自己跳，都认不准，不当身份。远程代理 / 跳板不在这次范围（跨网段用现有跳板机即可）。

宁可少记，不要记错：

1. 会对某台机器动手的工具，自己声明「动手范围是眼前那扇窗」。
2. 执行时问这扇窗连的是谁：本机 → `local`；远程 → `user@host`（与主机档案同一套身份）。
3. 这次 run 里，某台至少在那扇窗里被动手过一次，才算操作过。只开窗、没跑命令/动文件，不算。
4. 幕后本机命令不算「对主机动手」——没开终端就只动个人。
5. 写进某台时，只把**落在这扇窗上的**执行记录交给它；并写明「这份是某某这条连接的」。记录里已经明显跳到别处，这台这轮不更新（交给现有「值不值得记」那次判断，不靠拆命令、不靠提示符）。
6. 用户自己在窗里跳、我们看不见：和今天终端页同一局限，不追。

## 写

| 这场对话 | 写哪里 |
|---|---|
| 助手，只聊天 / 只写文档 / 只幕后本机命令 | 只写 `personal` |
| 助手，在看得见的本机窗里动手 | `personal` + `local` |
| 助手，在一台或多台远程窗里动手 | `personal` + 各台的 `user@host` |
| 本机 / 远程终端页（本来就是对着那台） | 保持现状：写那台；若同一 tab 里分屏动了另一台，也按上面的「对哪台动手」补写那台 |

每份文档只吃**属于它的**执行记录。个人那份继续只收偏好/约定；主机那份只收那台的事实。仍由现有的「值不值得记」判断，不是整场对话原文复制。

## 读

- 助手默认注入个人记忆（不再误用本机那份）。
- 这场对话里已经开着终端时，再注入那些窗对应主机的已有记忆。
- 终端页照旧注入自己那台。助手这边新开的窗，不为此打断当前前缀缓存；下一轮或下次从终端打开那台时再看见。

## 改哪些

| 模块 | 文件 | 做什么 |
|---|---|---|
| Agent SPEC | `electron/services/agent/SPEC.md` | 设计目标（已写） |

## 明确不做

- 关切 / 唤醒的记忆规则
- 把一场对话整份复制到每台主机
- 只开窗、没动手也更新
- 靠提示符或猜命令认「现在在哪台」
- 部署远程代理来治记错
- 为新开的那台打断当前前缀缓存
- 旧的观察日志式「主机记忆」写入（那条路径目前没有调用方，不复活）

## 验收

1. 助手只聊天：个人记忆可能更新，本机/远程主机记忆不动。
2. 助手打开远程 A 并在那扇窗跑了命令：A 的记忆更新；从终端页打开 A 能看见。
3. 同一场里又对远程 B 动手：A、B 各更新各的。
4. 只开了窗、没在那扇窗动手：不更新那台。
5. 助手开着 A 的终端再发一条：能看见 A 已有的记忆。
6. 在 A 的窗里又跳到别处且执行记录里看得出来：A 这轮不更新，不把别处的事实写入 A。
